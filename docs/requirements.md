# 機能要件

元資料: 要件定義書 ver0.4.0。資料間の食い違いについての決定事項と、保留中の点は [spec.md](spec.md) を見てください。

## ロール

| ロール | 説明 | DB での表現 |
| --- | --- | --- |
| 利用者 | 大会にエントリーして問題を解く | `is_admin = false` かつ `is_organizer = false` |
| 大会運営 | 問題を作り、大会を作成・開催する。利用者の中から管理者が任命する | `users.is_organizer` |
| 管理者 | 問題を承認・拒否し、ユーザーのロールを変更する。大会運営とは別のロール。アカウントは事前に登録しておく | `users.is_admin` |

- ログイン後の遷移先: 利用者は TOP ページ（大会一覧）、大会運営・管理者は運営メニュー画面。
- ロールの変更は管理者だけが行える。自分自身のロールは変更できない。変更は対象ユーザーの次回ログインから反映される。

## ユーザー管理

- **新規登録**: メールアドレスを入力 → 認証メールが届く → メール内の URL から登録画面を開く → ユーザー名とパスワード（英数字8文字以上）を入力 → バリデーション後にアカウント作成（ロールは利用者）。
- **ログイン**: メールアドレスとパスワードで認証する。
- **パスワード変更**: ログイン中に、現在のパスワードと新しいパスワードを入力して変更する。
- **パスワードリセット**: ログイン画面の「パスワードを忘れた場合」から登録メールアドレスを入力し、リセット用 URL をメールで受け取る。URL の有効期限は発行から1時間。期限切れなら申請からやり直す。設定後はログイン画面へ遷移する。
- **ログアウト**: 確認ポップアップで「OK」を選ぶとログアウトし、ログイン画面へ遷移する。

## 問題管理

問題は「仮保存 → チェックリクエスト（確認待ち）→ 承認 / 拒否」の流れで管理する。大会に出題できるのは承認済みの問題だけ。

- **登録**: 大会運営・管理者が、問題文、テストケース（標準入力と期待出力、1つ以上）、模範解答コード、難易度、備考（問題についての補足メモ）を入力して仮保存する。
- **試し実行**: 登録画面で言語を選び、模範解答コードを全テストケースで実行する。テストケースごとの結果と期待出力との一致を表示し、テストケースや模範解答の不備を確認できるようにする。
- **チェックリクエスト**: 大会運営が仮保存問題一覧から送信すると、管理者にメールで通知し、問題の状態が「確認待ち」になる。拒否されたら修正して再リクエストできる（承認されるまで繰り返す）。
- **リクエスト済み問題の一覧**: 状態（確認待ち・承認済み・拒否）を表示する。拒否された問題は拒否理由と修正依頼の内容を確認できる。
- **承認・拒否**: 管理者が問題ごとに判断する。承認は「許可」ボタン、拒否は理由と修正依頼をテキストで入力する。
- **チェックレスポンス**: 管理者がリクエスト中の全問題を承認または拒否し終えたら、送信ボタンで大会運営にメールで通知する。
- **閲覧（運営側）**: 大会運営・管理者が承認済みの問題を一覧で確認できる。
- **編集・削除の権限**:
  - 大会運営が編集できるのは、自分が仮保存した未承認（確認待ち・拒否）の問題だけ。
  - 承認済みの問題の編集・削除は管理者だけ。
  - 削除は確認ポップアップで「OK」を選んでから行う。

## 大会作成

- **作成**: 大会運営・管理者が、大会名、開始日時、制限時間、概要、出題問題、順位表の更新停止の設定を入力し、下書きとして保存する。
  - 制限時間は大会全体で1つ（問題ごとの制限時間はない）。
  - 出題問題は承認済みの問題から選ぶ。
  - 順位表の更新停止は任意。「大会終了の何分前に止めるか」で指定する。設定しなければ大会終了まで更新する。
  - 下書きは公開するまで利用者に表示しない。
- **公開**: 下書きを最終確認して公開すると、大会のエントリーページが利用者に表示される。
- **通知**: 大会が公開されたら、利用者にメールを送る。このメールでメール認証も兼ねる（卒業年次のアカウントがいつ無効になるか決まっていないため、受信できるかを大会ごとに確かめる）。TOP ページにも大会参加へのリンクを表示する。

## エントリー

- **参加申請**: 利用者が TOP ページまたはメールの URL から大会詳細を開き、エントリーする。エントリー情報は DB に登録する。大会開始30分前に参加が確定し、それ以降は辞退できない。
- **メール認証**: エントリーの前に、登録メールアドレスで今も受信できることを確認する。
  - 未認証の利用者がエントリーしようとすると、メール認証画面へ遷移する。認証が完了するまでエントリーできない。
  - 認証済みかどうかは、ユーザーの認証日時と大会の公開日時を比べて判定する。
  - 画面を経由しない操作でも、エントリー処理の時点で認証済みかを確認する。
  - 認証メールはメール認証画面から送信する。メール内の URL を開くと認証日時を現在日時に更新し、ログイン画面（認証完了の案内つき）を経由して大会詳細画面へ遷移する。大会通知メールから来た場合も同じ流れになる。
- **辞退**: 参加中の大会詳細ページから辞退すると、参加者リストから外れる。辞退できるのは参加が確定する前（大会開始30分前まで）だけ。
- **参加者閲覧**: 大会運営・管理者が、大会管理画面から参加者一覧を確認できる。

## 大会の開催・終了

- **開催**: 大会運営が公開済みの大会の開始ボタンを押すと、大会が始まって制限時間のカウントが始まり、提出の受付を開始する。問題は事前にエントリーした利用者にだけ表示する。
- **問題の閲覧（利用者）**: 大会ページの問題一覧から問題を選び、問題文を読む。
- **言語選択**: 問題ごとに対応言語（Java、Python、JavaScript、PHP、C、C++、C#）から選ぶ。テスト実行と採点は選んだ言語で行う。
- **テスト実行**: 提出前に、記述したコードを問題のテストケースで実行して結果を確認できる。何度でも繰り返せる。結果は DB に保存しない。
- **提出**: 制限時間内に限り提出できる。提出時は「提出後は修正できない」ことを確認するポップアップを出す。提出後はコードを修正できない。提出すると採点が始まる。
- **実行・採点**: 提出されたプログラムをメモリ上限の範囲で実行し、テストケースの期待出力と照合して正誤を判定する。
- **得点（減点式）**: `スコア = 100 × (1 − 0.01 × 分数) × (正解したテストケース数 ÷ 全テストケース数)`。分数は提出までにかかった時間。端数は丸め、最低点より下がらないようにする（起点・最低点の値・丸め方は未決。[spec.md](spec.md) を参照）。
- **採点結果の確認**: 採点が終わると結果（正解したテストケースの数と得点）を表示し、問題一覧に戻って次の問題を選べる。
- **不正対策**:
  - 利用者ごとにサンドボックスを分け、それぞれにメモリ上限を割り当てる。上限を超えたコードは実行を止めてエラーを表示する。
  - コード入力画面ではコピー＆ペーストを禁止する。IDE は使わせず、アプリ内のエディタだけでコードを書かせる。
- **閉幕**: 制限時間が来ると大会は自動で終了する。終了後は提出を受け付けず、最終結果を確定する。
- **結果公開**: 大会終了後、大会運営が結果を確認し、問題がなければ公開する。公開した結果が最終結果になる。
- **最終結果の閲覧**: 利用者は大会詳細画面で最終結果（順位・得点）を見られる。公開前は表示しない。
- **大会履歴**: 終了した大会を過去3年分まで一覧で確認できる（利用者・大会運営・管理者）。大会を選ぶと、順位とスコア（上位10名と自分の分）と、出題された問題を表示する。

## スコアボード

- 大会中、大会運営・管理者が順位表（順位・ユーザー名・得点）を見られる。
- 採点結果が確定するたびに得点を再計算し、順位表をリアルタイムで更新する。画面も自動で最新の順位表に切り替わる。
- 大会作成時に更新停止（終了の何分前か）を設定した場合は、その時点で更新を止め、以後は停止時点の順位表を表示し続ける。

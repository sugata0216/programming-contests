# アプリ仕様（概要）

学内向けのプログラミング大会プラットフォームです（TechFUL の「大会運営」機能に相当するもの）。大会運営者が問題を作り、管理者が承認し、大会を開催します。利用者はブラウザ上でコードを書いて提出し、システムが自動で採点して順位表を更新します。

| --- | --- | --- |
| [requirements.md](requirements.md) | ロール、機能要件、業務ルール | 要件定義書 ver0.4.0 |
| [screens.md](screens.md) | 画面一覧と画面ごとの役割 | 外部設計書 ver1.0 の画面設計 |

元資料どうしで食い違っていた点の決定事項と、保留中・未決の点は、この下にまとめています。

## 前提となる技術

- 採点（コードの実行）には **Judge0** を使います（`submission_results.judge0_token` と `languages.judge0_language_id` が前提にしています）。
- DB は **PostgreSQL**、データアクセスは **MyBatis** です。
- 画面は Thymeleaf テンプレートで作ります。
- 対応言語: Java、Python、JavaScript、PHP、C、C++、C#

## 決定事項（資料間の食い違いの解消）

元資料どうしが食い違っていた点について、ユーザーに確認して決めた内容です。各ドキュメントにも反映済みです。

1. **DB は DB定義.xlsx を正とする**: 外部設計書の「3. DB設計」（genres、titles、choice_1〜4 など）は別アプリ（四択クイズ）のもので、使いません。
2. **大会の状態**: 画面上の4状態は `tournaments.status` と `is_published` の組み合わせで表す。下書き＝未公開かつ `before`、公開済み＝公開かつ `before`、開催中＝`ongoing`、終了＝`after`。
3. **順位表の更新停止**: 大会終了の何分前に止めるかを `tournaments.stop_remaining_time`（分）に入れる。NULL なら大会終了まで更新する。
4. **得点**: 端数は丸める。得点には最低点があり、それより下がらない。
5. **問題の状態**: `questions.is_draft` は下書きかどうか、`is_approved` は承認済みかどうか、`request_questions.question_status` は承認審査の状態を表す。`pending` は「保留」。
6. **参加の確定**: 大会開始30分前に参加が確定し、それ以降は辞退できない。
7. **テスト実行の結果**: 提出前のテスト実行の結果は保存しない。

## 保留・未決事項

ここに挙がっている点を実装で決める必要が出たら、推測で決めずにユーザーに確認してください。

1. **（保留）結果公開を表すカラムがない**: 大会終了後に運営者が「結果を公開」する機能がありますが、`tournaments` に結果公開済みかどうかを持つカラムがありません。
2. **（保留）メール認証の判定に使う公開日時がない**: 要件では「ユーザーの認証日時（`users.authenticated_at`）と大会の公開日時を比べる」とありますが、`tournaments` に公開日時のカラムがありません。
3. **得点計算の細部**: 次の点がまだ決まっていません。
   - 減点式の「分数」の起点（大会開始か、問題を開いた時刻 `users_questions.opened_at` か）
   - 最低点の値
   - 丸め方（四捨五入・切り捨て・切り上げのどれか）
